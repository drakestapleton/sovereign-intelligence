## What AIEN is trying to build

AIEN, led by Drake Stapleton with agents as collaborators, is building persistent intelligent computing on owner-controlled hardware: an operating system, an explicit computational language, a machine realization layer, a host runtime and a reproducible verification/learning loop. The ambition is a system that turns an objective into explicit conditions, discovers how the available machine can realize them, verifies effects, acts and learns from the result. It is **research-grade**, not a finished autonomous operating system or a promise of flawless verification.

The short working doctrine is:

> Weights suggest. Programs explain. Omega verifies. Physics authorizes. Evidence teaches.

Read that with the [canonical responsibility boundaries](https://github.com/aien-dev/aien-architecture-mv/blob/main/PLAN_AUTHORITY.md): `ATLAS AWAKENS. ALLEN INTENDS. AIEN PROPOSES. OMEGA DEFINES. FORGE REALIZES. AEGIS VERIFIES. HARDWARE ACTS. EVIDENCE TEACHES.` These are responsibilities, not a literal turn order. FORGE is physical realization and policy, not a substitute security authority. AEGIS is the cross-cutting invariant checker, not automatically the repository named `aegis-runtime-mv`.

- **Weights/model fluency propose**, never establish truth, permission or completed work. A persuasive explanation, generated program or model review is not a measured result.
- **Programs make claims inspectable**: inputs, transformations, invariants, failure conditions and allowed effects. Omega aims to separate computational meaning from disposable machine representation. A semantic identity is not proof that a program is correct or authorized.
- **Physics constrains realizability**: memory movement, locality, bandwidth, queues, scheduling and device/OS interfaces must be established, not invented. Removing a userspace library does not establish independence from the kernel, firmware or driver.
- **Evidence teaches**: execute a declared experiment, retain failures and controls, bind observations to source, toolchain, command and environment, then distill a reusable lesson. This is experience-first learning, not turning fluent text into knowledge by storing it.
- **Omega is the forward first-party implementation language**. Existing C, Rust, shell and other infrastructure are unfinished migration, not evidence that the destination changed. Qualify replacements, migrate actual consumers and remove superseded implementation while preserving history and immutable receipts. Do not rename foreign source or alter language statistics to pretend a migration happened. External interfaces and independent oracles need explicit roles.

## Which authority answers which question?

In [aien-architecture-mv](https://github.com/aien-dev/aien-architecture-mv):

1. [PLAN_AUTHORITY.md](https://github.com/aien-dev/aien-architecture-mv/blob/main/PLAN_AUTHORITY.md) defines precedence.
2. [doctrine/ARCHITECTURE.md](https://github.com/aien-dev/aien-architecture-mv/blob/main/doctrine/ARCHITECTURE.md) owns responsibilities and terminology.
3. [doctrine/ROADMAP.md](https://github.com/aien-dev/aien-architecture-mv/blob/main/doctrine/ROADMAP.md) owns milestone IDs and status, including historical limitations.
4. [CURRENT_EXECUTION_PLAN.md](https://github.com/aien-dev/aien-architecture-mv/blob/main/CURRENT_EXECUTION_PLAN.md) owns cross-project sequence. Read later dated corrections, not just its opening baseline.
5. [ADRs](https://github.com/aien-dev/aien-architecture-mv/tree/main/docs/adr) own recorded decisions. Check status and amendments; an ADR filename or merged prose is not implementation evidence.
6. The [capability register](https://github.com/aien-dev/aien-architecture-mv/blob/main/docs/capability-register/register.tsv) (aien-architecture-mv [#345](https://github.com/aien-dev/aien-architecture-mv/pull/345), merged 2026-10-30 as `5821a6acae2d01d998dfb2782527c16abbe604be`) is the record for CUDA-replacement capability. Each row gives the owner repository, the exact commit, the arch it ran on, an evidence level and an evidence file at that commit. `tools/capreg/capreg.om` checks it and refuses a row whose rev is not a 40-hex sha or whose evidence is not `aien-dev/<repo>@<sha>:<path>` or `register:<path>`; `AIEN_OMC=<omc 734f0a39…> sh tools/capreg/gate.sh` runs the fixtures, the register and a planted bad row, and reports NOT_RUN (exit 3) for any other compiler. Confirm each row you quote against its cited file. A register row indexes evidence; it is not evidence itself, and code and receipts still win when the two differ.

Component code and reproducible evidence win for what actually runs. Architecture wins for ownership and intended cross-project sequence. Do not create a competing master plan to resolve a contradiction; record it and repair the proper authority.

## Status discipline and known source drift

Keep **proposed**, **implemented**, **verified**, **qualified** and **deployed** separate. Report exact repository/commit, command, backend, date, verdict and exclusions. NOT_RUN, BLOCKED_HARDWARE, BLOCKED_OPERATOR and MISSING_IMPLEMENTATION never mean PASS. Host execution on a machine with a GPU is still host evidence; QEMU evidence does not qualify physical hardware; a single kernel parity test does not qualify serving a complete model. A merged PR is not a release, an open PR is not an available feature, and neither proves what binary is running.

**Merge is not Alpha.** The inspected [Omega workflow](https://github.com/aien-dev/omega-mv/blob/main/.github/workflows/aien-verification.yml) header (frozen GitHub copy) says hosted checks were advisory and never gated merges; that stays true of any check result attached to a Radicle patch. A desk merge of a Radicle patch puts a commit on Radicle `main`; it is not Alpha. `alpha/*` tags still require a signed full Spark bundle for a commit on `main`. Inspect the bundle's actual backends and coverage before saying hardware-qualified. Do not generalize one repo's workflow or historical README to all merge policy; never request a merge without authority.

**A READY hand-off is a merge request (Drake, 2026-10-31; Radicle form 2026-11-07).** The old `ready-to-merge` GitHub label merged any open, clean PR with no review, no status-check requirement and no Spark run; on 2026-10-31 an agent labelled aien-sovereign-core-mv #887 and #888 and both merged within a minute, unreviewed. The GitHub pipeline is frozen, and the same discipline now applies to Radicle: a READY file or desk `READY` line that names a full head sha asks the publishing lane to open a patch and the desk to merge it. Hard rules for agents: never add `ready-to-merge` or `automerge` anywhere, never self-merge or self-review a patch, and never treat a published patch as approved; the desk merges only after a signed independent review of that exact head, and any new head needs a new review. Mark at most three changes ready at once so they are reviewed in batches, and resolve or split out every open question before a change is marked ready, rather than writing that merging accepts the text as drafted. A skipped, neutral or NOT_RUN check is not a pass.

**Repository default-branch protection rulesets across `aien-dev`.**
- **Strict PR-only / zero-bypass (`main-protected`)**: Since 2026-10-25, `aien-dev/omega-harness` (25838607), `aien-dev/omega-bridge` (25838629) and `aien-dev/omnet` (25852242) carry an active branch ruleset named `main-protected` on default branch `main`: deletion, non-fast-forward and pull-request rules, zero required approvals, no bypass actors (`bypass_actors: []`), all three merge methods allowed, `require_extra_approval_for_unattributed_changes: false`. A direct `git push origin HEAD:refs/heads/main` fails with `GH013: Repository rule violations found ... Changes must be made through a pull request`. The zero-approval settings exist so the labeled auto-merge pipeline keeps working, not because review is unnecessary.
- **Admin-bypass PR protection (`main-protect`)**: `aien-dev/omega-mv` (25770320) and `aien-dev/aienux` (25770328) carry ruleset `main-protect`: deletion, non-fast-forward and pull-request rules, with `require_extra_approval_for_unattributed_changes: true` and an `OrganizationAdmin` bypass (`bypass_mode: "always"`).
